# OpenSurge Agent Wiki

Agent Wiki 为人和 AI 提供项目的领域地图、当前工程契约与证据入口。
按问题进入已知来源或代码；需要理解跨主题关系时再读 Concept。
面向操作者的安装、配置和使用说明集中在 [docs/user](../user/README.md)。

## 信息职责

| 位置 | 维护什么 |
| --- | --- |
| `wiki/concepts/` | 概念、关系和职责边界；必要时用简单结构图，并按问题指向来源 |
| `wiki/index.md` | 主题与来源的导航 |
| `sources/` 根目录 | 项目定位、API、开发、分发与构建发布说明 |
| `sources/decisions/` | 当前领域契约、具体规则、支持范围与设计理由 |
| `sources/validation/` | 可复用方法、通过标准，以及简短的已知证据范围与直接链接 |
| `tasks/` | 按需保留跨会话接续或复杂调查现场 |
| `tasks/finished_archived/` | 已结束的既有任务、计划与执行记录，默认隔离检索 |

Concept 可以大胆抽象。字段、匹配条件、优先级、调用步骤、异常处理与验证命令由对应
source 维护；Concept 保留理解系统必需的关系与职责边界。图与文字遵循同一尺度。
一个来源不必配一页 Concept，一个 Concept 也可以连接多个来源。

## 阅读与维护

从 [索引](wiki/index.md) 找到本次问题的来源；已知入口可直接进入。
回答支持或验收问题时读取 [证据入口](sources/validation/evidence-map.md) 指向的记录，
并核对版本、环境和路径。旧结果不能直接代表当前 checkout 已通过。

长期实现变化随代码更新对应的主要来源；只有概念关系或入口变化时才更新 Concept、
索引与 AGENTS。概念关系未变时，无须随实现细节同步修改。
精简前先迁移 Concept 独有且有效的规则，核对重复内容的差异，再移除重复描述。
用户操作变化同步相应用户指南，工程规则不在用户指南中另建权威副本。

重要 source 开头注明维护范围和相邻入口。验证方法只随环境前提、命令、通过标准或结论
边界变化而更新，不复制整份自动化断言，也不追加每次执行的日期和通过报告。

单次执行的日期、被测提交或差异、环境、结果、证据位置和未覆盖项保留在提交/PR 或已有
任务记录中。新证据影响能力判断、暴露阻塞或实现变化要求复验时，更新证据入口的摘要与
领域限制；普通测试不新建证据条目。未收录不等于不支持，文档核对点不冒充被测版本。

默认不建任务文件，需要接续时先用一个 Markdown，复杂调查再拆目录。结束的既有记录
移入 `tasks/finished_archived/`，修复引用；归档前提炼有效知识并保留重要结果的直接入口。
没有任务文件不为归档补建台账，单份报告不包一层目录或 README。

普通递归检索遵守根目录 `.ignore`。验收、回归、版本比较或资料不足时，沿证据链接或用
`rg --no-ignore` 定向追溯；索引不累积历史清单，归档也不进入 `.gitignore`。
本目录当前手工维护；本地编译状态如 `.llmwiki/` 不进入 Git，也不要求机械刷新整条文档链。
